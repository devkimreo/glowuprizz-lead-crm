# 자동화 테스트 시나리오

## 목적

리드마그넷 CRM의 핵심 흐름이 정상적으로 연결되는지 확인하고, 잘못된 입력·미인증 접근·운영자 간 데이터 접근 및 업로드 HTML 실행과 관련된 실패와 보안 경계를 검증한다.

테스트는 다음 두 계층으로 구성한다.

- API 및 서버 테스트: `src/app.test.ts`
- 실제 브라우저 E2E 테스트: `scripts/e2e.mjs`

실행 방법은 프로젝트 루트의 `README.md`를 따른다.

## 핵심 성공 흐름

| 단계 | 검증 내용 | API 테스트 | 브라우저 E2E |
|---|---|:---:|:---:|
| 운영자 로그인 | 올바른 계정으로 로그인하고 인증 세션을 발급받는다. | O | O |
| HTML 폼 등록 | `form` 요소가 있는 HTML 파일을 등록하고 DB에 저장한다. | O | O |
| 캠페인 생성 | 등록된 폼을 선택해 캠페인을 생성한다. | O | O |
| 배포 링크 생성 | 캠페인의 채널별 공개 링크를 생성한다. | O | O |
| 방문 기록 | 공개 링크 방문을 캠페인과 채널 기준으로 저장한다. | O | O |
| 공개 신청 | 방문자가 입력한 폼 데이터를 CRM 신청 정보로 저장한다. | O | O |
| 캠페인 성과 | 방문·순 방문자·신청·전환율을 계산한다. | O | O |
| 채널 성과 | 채널별 방문·순 방문자·신청·전환율을 계산한다. | O | O |

API 성공 테스트는 위 단계를 하나의 연결된 시나리오로 실행하고, 방문 1건·순 방문자 1명·신청 1건일 때 전환율이 100%인지 확인한다.

브라우저 E2E 테스트는 실제 Chrome에서 다음 사용자 흐름을 수행한다.

```text
로그인 → 폼 등록 → 캠페인 생성 → Instagram 링크 생성
→ 공개 폼 작성 및 신청 → 캠페인 성과 상세 확인
```

## 실패 흐름

| 시나리오 | 기대 결과 | 테스트 위치 |
|---|---|---|
| 미인증 상태에서 관리자 API 접근 | `401 Unauthorized` | `src/app.test.ts` |
| 잘못된 이메일 또는 비밀번호로 로그인 | `401 Unauthorized` | `src/app.test.ts` |
| HTML이 아닌 파일 업로드 | `400 Bad Request` | `src/app.test.ts` |
| `form` 요소가 없는 HTML 업로드 | `400 Bad Request` | `src/app.test.ts` |
| 존재하지 않는 공개 링크로 방문 기록 | `404 Not Found` | `src/app.test.ts` |
| 형식이 잘못된 방문자 ID로 신청 | `400 Bad Request` | `src/app.test.ts` |
| 64KB를 초과하는 신청 데이터 전송 | `413 Payload Too Large` | `src/app.test.ts` |

## 인증 및 권한 검증

| 검증 항목 | 기대 결과 |
|---|---|
| 관리자 API 인증 | 유효한 세션 쿠키가 없으면 접근할 수 없다. |
| 운영자별 데이터 격리 | 다른 운영자가 소유한 캠페인의 성과를 조회하면 `404`를 반환한다. |
| 세션 저장 | 원본 세션 토큰이 아닌 SHA-256 해시를 DB에 저장한다. |
| 세션 쿠키 | 브라우저 JavaScript가 읽을 수 없는 HTTP-only 쿠키를 사용한다. |

세션 저장과 쿠키 설정은 구현 코드로 보장하며, 현재 자동화 테스트는 미인증 접근과 다른 운영자의 캠페인 조회 차단을 직접 검증한다.

## 업로드 HTML 격리 검증

업로드된 HTML은 신뢰할 수 없는 코드로 취급한다.

| 검증 항목 | 기대 결과 | 검증 방식 |
|---|---|---|
| iframe sandbox | `allow-scripts allow-forms`만 허용한다. | API 테스트 |
| 동일 출처 권한 | `allow-same-origin`을 부여하지 않는다. | API 테스트 |
| 스크립트 제한 | 요청별 nonce가 포함된 CSP를 적용한다. | API 테스트 |
| 원본 HTML 노출 | 업로드 HTML을 호스트 문서에 평문으로 직접 삽입하지 않는다. | API 테스트 |
| 관리자 쿠키 접근 | sandbox 내부에서 `document.cookie` 접근이 차단된다. | 브라우저 E2E |
| 폼 제출 연결 | 서버가 제공한 브리지에서 신청 데이터만 부모 문서로 전달한다. | API/E2E |

## 테스트 코드 대응

### `src/app.test.ts`

1. 미인증 관리자 요청과 잘못된 로그인 거부
2. 폼 등록부터 성과 계산까지 핵심 성공 흐름
3. 잘못된 업로드와 존재하지 않는 공개 링크 거부
4. 운영자 간 캠페인 데이터 접근 차단
5. 업로드 HTML의 sandbox 및 nonce 기반 CSP 격리
6. 잘못되거나 과도하게 큰 공개 신청 데이터 거부

### `scripts/e2e.mjs`

실제 Chrome을 이용해 관리자와 방문자 화면을 연속으로 조작한다. 성공 시 로그인부터 성과 화면까지 완료하고, 업로드 iframe이 관리자 쿠키를 읽지 못했음을 함께 확인한다.

E2E 테스트는 실행할 때마다 고유한 이름의 폼과 캠페인을 생성하므로 기존 데이터와 이름이 충돌하지 않는다.

## 테스트에서 제외한 범위

다음 항목은 최초 과제 범위에 포함되지 않거나 현재 구현하지 않은 외부 연동이므로 자동화 테스트 대상에서 제외한다.

- 실제 AI 모델 연동
- 외부 CRM, 문자 및 알림톡 연동
- 광고 플랫폼 게시 및 성과 동기화
- 결제, 계약 및 상담사 관리
- 여러 브라우저 엔진 간 호환성 테스트
- 부하, 장애 복구 및 장시간 안정성 테스트

## 판정 기준

- API 및 서버 테스트가 모두 통과해야 한다.
- 브라우저 E2E 테스트가 오류 없이 종료되어야 한다.
- 핵심 성공 흐름의 마지막 단계에서 캠페인 전환율이 표시되어야 한다.
- 실패 흐름은 정의된 HTTP 상태 코드로 거부되어야 한다.
- 업로드 HTML은 관리자 인증 정보에 접근할 수 없어야 한다.
